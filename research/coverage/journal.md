## 2026-11-12 — до первого круга

Уроки прошлых заходов:

- Время уходило на перезапуски игры и на ситуации, поставленные поштучно. Дальше: одна игра
  на круг, сброс мира вместо перезапуска, Lua — через `bridge-reload`.
- Проверялось только то, что заранее было в списке. Дальше: захват всего, что ожило.
- Вступительная сцена блокирует бой — `game.fast_scenes(20)` первым делом после сброса.
- Мёртвый отряд и обучающие окна ставят сервер на паузу — `Stage.Protect`, `Stage.Quiet`.
- Много мелких вызовов моста подряд дают гонку за файл — объединять в один вызов.
- Сверка с конструкторами macOS выглядела подтверждением, пока не была проверена на
  испорченных раскладках (0 из 52). Любой новый тест сначала проверять на заведомо неверном.
- `tags.py` не перезапускать: стирает файлы тегов.

Идеи на круг 1: `Stage.Unblock`/`Scout`, `Probe.CaptureAll` + `seen\`, тур по Наутилоиду,
исполнители на реплицируемые типы параллельно с игрой.

## 2026-11-12 — круг 1, Наутилоид

- Постоянный захват (`seen.py`) + тур (`tour.py`): за один запуск игры живыми увидено 1551 тип
  (до круга проверялись только типы из заранее составленного списка). Самые урожайные шаги:
  прыжок (21 новый тип), толчок и бросок (32), пачки заклинаний (5–40 каждая). Клавиши панелей
  (I, M, J, K, N, L, TAB) и поверхности не дали ничего нового — убрать из обязательных.
- Ошибка: шаг `key-ESCAPE` (две подряд инъекции Escape) вывел игру в главное меню; сервер
  выгрузил уровень, `QuickLoadCommand` из меню не сработал — пришлось перезапускать игру
  (минус ~5 минут и шаги после него). Шаг удалён. Правило: клавиши, открывающие системное
  меню, не нажимать; шаги с неизвестным исходом ставить в конец тура.
- Идея: загрузка сохранения из главного меню кодом (тогда такой сбой лечится без перезапуска).
- Правил `tour.py` во время его работы — безвредно, но трассировка показала чужие строки.
  Не править работающий скрипт.
- Решение (самостоятельно): добавлен второй статус раскладки `declared` — «объявлено по коду,
  вживую не сверено»; откат — вернуть `IN_BUILD = ("confirmed",)` в `generate.py`.

## 2026-11-12 — круг 2, первый акт (в работе)

- Переход в первый акт внутри той же игры: `GK.Stage.Level("WLD_Main_A")` — 36 с.
- «Конец игры» после сценарной смерти (диалог с «Мы»): сервер на паузе, загрузка не идёт,
  обе кнопки окна ведут из игры. Сделано: `GK.Stage.Guard` (страж: поднимает погибшего сразу),
  `tour.game_over` + `tour.restart` (тур сам перезапускает игру и идёт дальше).
- Пользователь: «диалоги не закрываются из-за окна подброса кубика, и таких ситуаций тысячи —
  ты должен уметь быстро с ними справляться». Сделано: `GK.Blocking()` / `GK.Unblock()` /
  `GK.RollNext()` (клиент): бросок проходится командой `UserTriggeredNextPhaseCommand` модели
  `gui::DCActiveRoll` (три фазы); обычное окно сообщения принимается. Правило: любое новое
  окно, на котором встал тур, сразу разбирается через `GK.ViewModels()` / `GK.Properties()` и
  добавляется в `GK.Unblock`, а не обходится разово.
- Пользователь: нужны «убивающие» утилиты и защита от смерти; знать о триггер-зонах.
  Сделано: `GK.Stage.Slay`, `Guard`; `GK.Stage.Triggers` (18 видов зон), шаги автотура по зонам.
- Сборка: раскладки исполнителей ссылаются на типы из других заголовков SE → `quarantine.py`
  (откладывает отвергнутое компилятором и пересобирает). В инструкцию исполнителям добавлено:
  только примитивы и собственные структуры.
- Самоконтроль: длинные фоновые задачи запускать с ограничением времени и сторожем по журналу.

## 2026-11-12 — замечание пользователя о простоях

«Это все должен был ты сам все эти простои обнаружить, а не я тебе говорить.» Все четыре
ускорения этого круга (бросок кубика, окно конца игры, ожидание сцен после сброса, таймеры
вместо событий) подсказал пользователь, хотя данные лежали у меня: в журнале тура были шаги
по 40 с с пометкой «timed out», сброс по 120 с, одинаковые паузы у шагов, которым они не нужны.

Что меняю:
- После каждого прогона первым делом смотрю не «что нового ожило», а «куда ушло время»:
  шаги дольше 20 с, шаги с пометками о таймаутах, время сбросов. Любой такой шаг — задача до
  следующего прогона, а не «тур их пропускает».
- Тур сам печатает итог: медиана шага, пять самых долгих, сколько раз ожидание упёрлось в
  потолок, сколько ушло на сбросы.
- Слово «таймаут» в журнале = неизвестное блокирующее состояние: сразу смотреть
  `GK.ViewModels()` и разбирать, не дожидаясь подсказки.
- Долгую задачу запускаю только после того, как правка под неё проверена отдельным вызовом.

## 2026-11-13 00:20 — осмысленные цепочки (указание пользователя)

«На основе готовых диалоговых деревьев и миссий начать более осмысленные цепочки действий.»

- `dialog_plan.py`: дерево диалога из индекса данных игры — вопросы, ширина выбора, броски,
  узлы торговли, вложенные диалоги, флаги-условия, которые диалог проверяет и сам не ставит.
  `plan()` даёт проходы: первые ответы, вторые ответы, проход с выставленными флагами-условиями.
- Автоответчик: политика ответа `pick` = first / second / third / last; вопрос, пришедший
  третий раз, получает последний ответ (нет вечных петель).
- Вид шага автотура `dialogtree`: самые «богатые» диалоги уровня по несколько проходов.
- Найдено при проверке вручную: (1) диалог появляется через ~3,7 с после запуска, а шаг тура
  считал игру «спокойной» уже через 3 с — ВСЕ прежние шаги диалогов обрывались раньше начала
  (ловил только общий выход из диалога). Исправлено: шаг сначала ждёт появления (`expect`).
  Это я должен был заметить по «act 3 с» у диалогов с десятками вопросов. (2) Узел Trade
  открывает окно торговли и диалог стоит: в `GK.Unblock` окно живёт 2 с и закрывается одним
  Escape с защитой от повторного нажатия.
- Ограничение: в `DB_Dialogs` зарегистрированы не все диалоги — самые богатые (например
  DEN_Apprentice_Cyanide, 40 бросков) запускает сюжет. Следующий шаг: запускать диалог по
  имени ресурса и участникам из индекса (dialog_speakers), и цепочки по целям Osiris (квесты).
- Оба тура перезапущены без пропуска сыгранного: прежние диалоги надо переиграть честно.
- 00:30 — сессия декомпиляции: покадровые Update систем с адресами в bg3.exe (856 из 913) и
  псевдокод macOS с настоящими именами рядом с Windows. Вписано в инструкцию исполнителям.
  Это открывает покрытие СИСТЕМ (сейчас 85 из 934): у системы теперь есть вход для чтения.
